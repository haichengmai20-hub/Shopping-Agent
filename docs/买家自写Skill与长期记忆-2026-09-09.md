# 买家自写 Skill 与长期记忆

同日后续更新：[刷新恢复修复](刷新恢复修复-2026-09-09.md) 已补齐缓存缺失时服务端恢复与当前导航保留，并在原用户标签页实测。使用固定页面地址保留演示买家身份；启动和数据保存位置见 [README](../README.md)。

本轮按用户要求，将个人 Skill 编写和长期偏好管理接到买家页面，并验证 Agent 实际读取、修改、删除。入口为 [本机页面](http://127.0.0.1:5174/) 左侧“我的 Skill”和“长期偏好”。已有会话可以直接恢复；仅旧会话绑定了不含新增工具的版本时，开启一次新选购使用新工具。

## 教程依据与实现取舍

参考归档教程：

- [第 6 章：长期记忆与用户偏好 Store](../../../2026-08-28/电商搜索Agent-基础部分/02%20Context工程篇/06%20长期记忆与用户偏好Store.md)：独立 PreferenceStore、like/dislike、写入和精确撤回工具、主 Agent 与检索子 Agent 注入、偏好指纹参与缓存隔离。
- [19-5：Agent Skill 渐进式能力加载](../../../2026-08-28/电商搜索Agent-基础部分/11%20Prompt工程篇/19-5%20Agent%20Skill%20渐进式能力加载.md)：只常驻名称和用途，使用时读取正文；正文指导方法，不新增工具权限。

教程第 6 章开头有“注入 system prompt”的概括，但 §5.1 的具体实现采用独立 hint 消息以保留静态缓存前缀。本轮沿用具体实现：每轮模型执行前从持久库读取最新偏好，替换旧 memory_hint；相关 like 按已有 selector 选取，dislike 全量保留。没有新增一套与 Agent 脱节的浏览器记忆。

个人 Skill 会随买家编辑而变化，因此元数据放到动态 personal_skill_catalog，而非全局静态 system prompt。公开审核方案仍沿用原审核库；买家自写内容只属于当前买家，不自动成为全局已审核知识。

## 页面使用

### 我的 Skill

填写名称、什么时候使用、方法与步骤，支持 Markdown 正文。保存后，回到选购输入 `/` 可选择；也可直接说“使用我的某某方案”，让 Agent 按目录调用读取工具。

每次编辑生成新修订和内容哈希。并发编辑时校验原版本，冲突不会覆盖别人的更新，页面保留未保存正文。删除立即从个人目录和斜杠菜单移除，旧修订不再可读取；不可变修订留作本机版本记录。个人 Skill 最多 50 个，名称 120 字、用途 400 字、正文 12000 字。文件和脚本执行不在本轮范围。

### 长期偏好

按“喜欢／避免”填写一条稳定偏好，支持添加、编辑和删除。保存到服务端 PreferenceStore，刷新页面、新会话、服务重启后读取同一持久数据。正在运行的本轮使用其已加载上下文，修改从下一轮开始生效。

也可在对话中明确要求：

- “记住我喜欢轻便的商品。”
- “把喜欢蓝色改成喜欢绿色，以后都按这个偏好。”
- “删除喜欢绿色这条长期偏好。”

对应工具为 remember_preference_tool、update_preference_tool、forget_preference_tool。修改按旧原文原子替换，旧条目不存在时不新建；删除精确匹配，不模糊删相似偏好。身份来自 ShoppingContext，工具不接受买家 ID，缺少可信上下文时拒绝写入。一次性预算、颜色例外仍放在本轮需求里。

## 存储与接口

个人 Skill 存于 DATA_DIR/buyer_skills.db，包含按买家隔离的当前版本指针和不可变修订。读取复核内容哈希、买家归属和当前有效版本。编辑个人 Skill 不改变全局 capability_digest，不使其他买家的会话失效。历史个人 Skill 工具输出正文会在下一轮清理，并保留调用配对；当前目录与偏好提示覆盖历史摘要中的旧资料。

长期偏好继续复用现有数据库或 JSON 适配器。SQL 修改在事务内完成；JSON 修改增加进程文件锁和临时文件原子替换，避免 API/worker 并发覆盖。浏览器仅持有当前表单状态，服务端是保存结果的权威来源。

| 接口 | 功能 |
| --- | --- |
| GET /commerce/my-skills | 当前买家个人 Skill 正文列表 |
| POST /commerce/my-skills | 创建个人 Skill |
| PUT /commerce/my-skills/{id} | 带 expected_version 更新 |
| DELETE /commerce/my-skills/{id} | 带 expected_version 删除 |
| GET /commerce/skills | 合并个人 Skill 与公开可用方案，仅元数据 |
| GET /commerce/preferences | 当前买家持久偏好 |
| POST /commerce/preferences | 新增；带 previous_statement 则原子替换 |
| DELETE /commerce/preferences | 请求体 statement 精确删除，正文不放 URL |

这些入口均复用 require_buyer 与现有 HMAC 严格身份模式。当前本机沿用项目原有开发身份模式；本轮未把它声明为已上线的账号登录系统。客户端不能提交 Skill 所有者、工具权限或系统指令级别。个人 Skill 正文始终为 reference_only，不免除真实交易确认。

## 本机版本启用边界

新增修改工具改变了工具契约，本机通过既有 Prompt 注册导入当前内容，并在已忽略的 .env 中配置 PROMPT_PIN_VERSION 启用新版本。原有全局 Prompt 部署记录、旧会话、历史资料没有清除或改写；旧会话保持原绑定，需要新选购使用新工具。

这是用户授权的本机功能交付与验证，不是正式候选 A/B 发布，也不意味着此前商品检索的全部 release 质量门禁通过。测试用个人 Skill 和偏好使用隔离买家；本机验收后删除测试条目，不为真实买家预设偏好。
