# 正式评测选集与证据清单

更新：2026-09-09。三条 runner 现在在调用模型、向量服务或 Agent 服务**之前**选择输入集，再计算该选集的指标；报告分桶不再代替真正的执行隔离。

## 选集规则

| 输入 | dev | release | all |
|---|---:|---:|---:|
| `eval/v1/product_retrieval.jsonl` | 105 | 45 | 150 |
| `eval/v1/knowledge_retrieval.jsonl` | 35 | 15 | 50 |
| `eval/v1/agent_cases.yaml` | 70 | 30 | 100 |

- `--split dev/release/all` 默认 `all`，保留早期未标注 split 数据集的运行方式。
- 显式 `dev` 或 `release` 要求原始输入的每条用例都有合法 split；缺标签、错标签、空选集、选中 ID 重复均直接报错，不回退到全集。
- Agent 的 `--only` 在 split 之后进一步过滤，缩小的执行标记为诊断，不代表完整 release。不存在的 ID 直接报错。
- `--dry-run` 只输出选集与配置清单，状态和门禁都是 `NOT_RUN`，不计算指标，不调用 Agent、Judge、embedding、reranker、Qdrant 或健康端点。
- 正式商品发布门禁须同时选择 `--split release --profile online-main`；知识门禁须同时选择 `--split release --formal-gates`。`all`、`dev` 或自定义阈值运行的门禁范围均为 `diagnostic`。
- Agent 的完整 `--split release` 禁止语义缓存，健康检查失败或缓存状态不明确时先阻断。局部用例仍可用于定位问题，但不代表发布验收。

## 零外部调用的检查

以下命令在工程根目录运行，只使用本地依赖和版本化数据。

```bash
.venv/bin/python scripts/eval/validate_datasets.py
.venv/bin/python scripts/eval/run_product_recall.py --dataset eval/v1/product_retrieval.jsonl --split release --profile online-main --dry-run --report-dir eval/verification/split-20260909
.venv/bin/python scripts/eval/run_category_recall.py --dataset eval/v1/knowledge_retrieval.jsonl --split release --formal-gates --dry-run --report-dir eval/verification/split-20260909
.venv/bin/python scripts/eval_regression.py --cases eval/v1/agent_cases.yaml --split release --dry-run --report-dir eval/verification/split-20260909
```

分开执行真实关键词检索，用于验证选集执行、指标汇总及原有硬约束：

```bash
.venv/bin/python scripts/eval/run_product_recall.py --dataset eval/v1/product_retrieval.jsonl --split dev --strategy keyword_2gram --report-dir eval/verification/split-20260909
.venv/bin/python scripts/eval/run_product_recall.py --dataset eval/v1/product_retrieval.jsonl --split release --strategy keyword_2gram --report-dir eval/verification/split-20260909
```

这两条是 `custom/diagnostic`，即使 PASS 也**不能**证明 `online-main` 通过。已批准的关键词全集基线仍可用原有方式独立验证：

```bash
.venv/bin/python scripts/eval/run_product_recall.py --dataset eval/v1/product_retrieval.jsonl --split all --strategy keyword_2gram --profile offline-fallback --baseline-file eval/v1/baselines/keyword_2gram.json --report-dir eval/verification/split-20260909
```

## 正式执行命令

下列命令会调用已配置的在线模型或检索服务。执行结果以对应日期的真实报告为准；dry-run 不能代替正式执行。

```bash
.venv/bin/python scripts/eval/run_product_recall.py --dataset eval/v1/product_retrieval.jsonl --split release --profile online-main --report-dir eval/releases
.venv/bin/python scripts/eval/run_category_recall.py --dataset eval/v1/knowledge_retrieval.jsonl --split release --formal-gates --report-dir eval/releases
.venv/bin/python scripts/eval_regression.py --cases eval/v1/agent_cases.yaml --split release --base-url http://127.0.0.1:8001 --report-dir eval/releases
```

Agent 应连接专门的评测实例，使用独立存储并关闭语义缓存；不要把含记忆写入的评测打到日常用户数据上。调用失败会写 `ERROR/BLOCK` 清单，指标失败返回非零退出码。关键词、`embedding_only` 或未知召回策略仍然无法通过 `online-main` 对 `embedding_rerank` 的要求；没有降低原门槛。

`eval/v1/baselines/keyword_2gram.json` 是既有 **all** 选集基线。本实现不会把它复制成 release 基线，也不会根据本次分数自动批准新基线。dev/release 如需基线比较，应提供对应选集的批准文件；release 文件必须声明 `split: "release"` 和与本次一致的 `selected_content_sha256`，同时保持 dataset 一致。不匹配会在外部调用前报错。

## 每次运行保留什么

每份 Markdown 报告旁边保存同名 `.manifest.json`。dry-run 仅生成 manifest。

| 字段 | 证据 |
|---|---|
| `selection` | split、原始/选中数量、完整性、选中 IDs、分桶数量、选中 JSON 内容 SHA-256 |
| `parameters` | K、profile、阈值、目标策略、门禁范围、缓存许可、是否 dry-run |
| `code` | git commit、dirty 状态、明确限定范围的工作区内容 hash、每个源文件路径/hash/字节数；包含未提交和新建源文件 |
| `prompts` | 当前应用 prompt 文件 hash；Agent 另含 Judge system prompt hash |
| `data` | 本次标注集、实际选择的版本化目录、知识文档与 manifest、所用基线的内容 hash；不读取用户数据库或 `.env` 内容 |
| `runtime` / `models` | Python/关键依赖版本、配置模型、Judge 请求模型、embedding 维度；配置值不冒充服务端实际使用值 |
| `services_configured` | 服务路径与 collection；移除 URL 凭据、query 和 fragment，不导出 API key |
| `execution` | 状态、门禁、实际检索链、汇总指标、含无结果题/不可回答题的逐条 observations、Agent 原始 trace、模型回退事件、运行前后输入内容是否一致 |
| `server_health` / `service_runtime` | Agent 服务健康端点返回模型与缓存状态；可选服务端启动时 app 源文件 hash、本地对应 hash、`matched/mismatch/unverified` |

工作区指纹包含 app、评测脚本、测试、前端源文件和部署/依赖配置等列明的文件范围；不把变动的报告输出或用户存储计入。同一运行期间代码或已列入的数据文件发生变化时，最终门禁降为 BLOCK，避免把运行开始的版本和结束时的代码混用。

服务端 app 指纹采用共享的 `app_source_fingerprint()` 算法，只核对 `.py/.yml/.yaml` 相对路径和内容。老服务未暴露该字段时保留 `unverified`；缺失不会被本地 hash 自动填成匹配。`matched` 也不证明依赖、数据卷、远端二进制字节或模型提供方版本一致。

## 本轮离线结果

数据自检通过；三条 release dry-run 分别选择 45/15/30 条。实际关键词检索结果如下，报告位于 `eval/verification/split-20260909/`：

| split | 总用例 | 正例 / 无结果题 | Recall@8 | Precision@8 | MRR | NDCG@8 | 过滤 / 无结果准确率 |
|---|---:|---:|---:|---:|---:|---:|---:|
| dev | 105 | 88 / 17 | 0.8636 | 0.6343 | 0.8750 | 0.8632 | 1.0 / 1.0 |
| release | 45 | 37 / 8 | 0.9189 | 0.6417 | 0.9189 | 0.9189 | 1.0 / 1.0 |

实际策略均为 `keyword_2gram`，执行期间输入 hash 未变化；以上只有离线诊断意义。线上主链此前暴露的 reranker 服务不可用问题仍需修复并真实重跑，不能由这些数字代替。

既有 `all + offline-fallback` 的 150 条批准基线也已实际复跑通过：Recall 0.880、Precision 0.636、MRR 0.888、NDCG 0.880；未修改基线或门槛。

## 用户动作与隔离执行

正式 Agent 的 15 条订单场景及旧 smoke 闭环已迁移为显式 `actions`。聊天轮次只能准备确认单；runner 先读取持久确认列表，核对 fixture 声明的 SKU、数量、分价、币种和完整地址，再使用服务端凭证 ID/hash 发出 `resolve` HTTP 请求。`approved` 必须为 fixture 字面布尔值，不从自然语言推断。动作前必须没有订单；动作后重读持久订单验证状态。拒绝、确认结果、动作请求和权威订单快照进入 trace，授权令牌不进入报告。

每次运行生成独立买家后缀，保护重复执行的记忆隔离。严格身份环境设置 `IDENTITY_MODE=hmac`、`SESSION_OWNER_BINDING=1`，由本地 `IDENTITY_HMAC_SECRET` 签发同一买家的 HTTP Bearer 和 WebSocket 子协议令牌。WebSocket 订阅还必须声明 buyer_id；令牌绝不发送给 Judge 或写进 URL。建议冻结源文件副本，在独立数据目录启动评测 API，并分别给商品、知识 runner 独立本地向量库以免并发文件锁。报告记录来源与冻结副本指纹；后续工作区变更不冒充同一版本验收。

独立 Hybrid 实验可用 `--strategy bm25`（零外部关键词实验）或 `--strategy hybrid_rerank --profile hybrid-experimental`。manifest 保留 variant 和逐题 vector/rerank 证据，门禁范围恒为 experiment。正式 online-main 仍使用 embedding_rerank；不因全局 Hybrid 配置或实验分数自动切换主链、基线或门槛。
