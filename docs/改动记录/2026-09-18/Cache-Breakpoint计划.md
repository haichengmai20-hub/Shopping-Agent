# 2026-09-18 · Cache Breakpoint 排查与实施计划

状态：**仅排查与计划，未实现、未启用。** 排查对应代码版本：`be13ff48`。

## 当前结论

实际模型请求没有显式 `cache_control` 标记，现有分层裁剪和摘要不等于供应商 Prompt Cache。SDK 可以解析部分缓存读取 usage，但缓存创建字段的完整计量仍需适配；没有证据证明当前网关透传缓存标记并实际生效。

相关入口：[统一模型调用](../../../app/infrastructure/llm.py)、[上下文 usage](../../../app/infrastructure/context_usage.py)、[结构化调用回归](../../../tests/test_structured_model_usage.py)。本次发布没有加入下述拟议配置或适配代码。

## 已讨论的实施顺序

| 步骤 | 拟实施内容 | 验证要求 |
| --- | --- | --- |
| 1. 网关预检 | 对主/备模型分别发送合成上下文，检查创建、重复前缀读取与前缀变化 | HTTP 200 不等于缓存生效，以真实 usage/服务端证据判断 |
| 2. 请求层适配 | 优先沿用 AgentScope Formatter 与统一模型层，只修改请求副本 | 不修改持久原文、AgentState 或工具调用配对 |
| 3. 断点策略 | 比较静态前缀与静态加历史边界；按最终内容块管理断点，初始最多 3 个 | 压缩或裁剪改变前缀时重算，不为缓存保留无效上下文 |
| 4. 完整计量 | 捕获供应商原始缓存创建/读取 usage，覆盖流式、结构化、重试、备用模型与摘要 | 缺失值保持未知，每次请求只结算一次；缓存 token 仍占上下文容量 |
| 5. 对照评测 | A 无显式标记、B 静态、C 静态加历史；8 场景 × 3 策略 × 3 次，共 72 次场景运行 | 隔离前缀、记录冷暖状态，成本包括创建、摘要、回查和重试；比较正确性、真实命中及延迟 |

拟议配置是 `PROMPT_CACHE_MODE=passthrough|explicit` 与 `PROMPT_CACHE_POLICY=static|static_history`，**当前不存在**。`passthrough` 仅表示不主动加显式标记，不能宣称关闭供应商隐式缓存。

## 失败处理与启用门禁

只有确认是参数不支持、且尚未输出内容时，才考虑去除标记后受控重试一次；不重放交易工具。按实际网关的协议约束决定标记位置，先完成能力验证，不照搬另一供应商的字段语义。

默认继续现有请求路径。功能正确、真实缓存证据、完整成本收益与普通轮 P95 劣化不超过 15% 的目标通过后，再决定启用；未提供计费字段时不宣称账单降幅。回滚目标是配置退回 passthrough，实施后再验证。
