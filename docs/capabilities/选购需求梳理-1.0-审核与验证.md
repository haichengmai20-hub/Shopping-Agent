## 为什么单独建立这份候选

原 `backpack-selection / 1.0` 的真实测试虽然证明读取链路可用，推荐质量仍未通过：混入腰包与收纳包，且出现未经目录证明的容量推断。本候选没有沿用该条目的发布结论，不把推荐失败改名成通过，也不修改或发布原背包草稿。

当前候选只复述用户已提供的需求，并最多问两个关键问题。没有明确币种就保持币种待确认；不按中文或收货国家推定人民币。不生成商品、SKU、商品价、运费、库存或到货时间。不把“优先”升级为必选，不放宽预算与材质排除，不为凑问题重复询问已知条件。用户同时给出未决定的两项预算时，保留冲突并请其决定。

`allowed_tools: []` 表示这份参考资料不需要额外工具，**并不自动移除主 Agent 原有工具或形成执行沙箱**。正文中的不检索、不交易要求仍须由实际运行结果验证；如果模型调用了这些工具，需求整理用例应失败，不能靠空白名单声称已阻止调用。已有交易确认机制继续生效，Skill 不能授权交易。

结果文件：[加载机制验证报告](shopping-needs-clarification.loader-verification.json)。15 项检查包括：草稿不可见、草稿不能读、未审核不能发布、空工具白名单可用、目录无正文、真实工具读取成功、ID/版本/hash 一致、`reference_only` 正文一致、买家排除条件不变、伪造版本拒绝、同版本篡改拒绝、工具扩权拒绝、撤销或旧 digest 读取拒绝、撤销后目录隐藏、审计身份如实标注自动化。

测试进程显式设置空的 `LANGFUSE_BASE_URL`、`LANGFUSE_PUBLIC_KEY`、`LANGFUSE_SECRET_KEY`，不读取或输出真实 Langfuse 凭据；没有调用外部模型、访问正式能力库或发送追踪数据。这份报告的 `real_model_behavior_verified` 和 `browser_structured_selection_verified` 均明确为 `false`。

## 三个真实行为用例

| 用例 | 必须观察到 | 不得出现 |
| --- | --- | --- |
| 缺币种：周末背包、轻便、预算300以内、寄中国 | 保留已知信息，询问币种；最多另问一个关键规格 | 默认人民币、编造容量重量、重复问国家、商品推荐 |

每个用例同时核对真实事件：选定版本实际加载成功、名称/版本/hash 一致、正常终态。除了真实 Skill 读取，不应出现商品、知识、联网、订单或偏好写入工具；不应展示新商品卡。只出现“已读取”还不足以说明用例通过，必须检查最终回答和工具事件。

## 发布范围与审核身份

既有 [能力版本管理说明](../Skill与审核策略版本管理-2026-09-09.md) 要求操作员查看正文和证据，再执行 import → review → publish；CLI 的操作员字段是声明式审计，不是企业身份认证。原背包审核卡另有“待人工审核”的具体要求，不能据此替背包条目补写虚构人名。

本轮用户明确要求页面能够实际唤起并执行 Skill，主任务据此在真实功能用例通过后将本方案启用到**本机演示工程**。审核记录的 actor 为 `codex-local-functional-review`，发布 actor 为 `codex-user-authorized-local-demo`；证据注明自动化审查和用户本轮授权，不冒充人工审核。这是用户授权的本地功能交付范围，不是生产效果门禁通过。不能写成用户亲自审过正文，也不能拓展为允许发布未经验证的商品推荐策略。

启用动作已由主任务统一执行。发布后有效能力集合发生变化，旧会话可能要求新建选购；使用页面时应选择新会话。若修改本方案的正文、证据、scope、工具声明或有效期，应建立新版本并重新验证，不覆盖已经发布的 1.0。

## 结构化选择待复核点

- 服务端只接受真实发布且未到期/撤销的 ID、版本和 hash，不能信任前端传来的正文、标题、状态或权限声明。
- 选择进入本次 run 的权威请求身份；同 run 重试若更换选择须冲突，不能复用旧结果冒充执行新版本。
- 实际读取失败、版本变化、取消或未读取时不能显示读取成功；新 run 清空旧读取记录。
- 网络断开后重连复用 journal 中同 run 的真实事件，不重新读一次 Skill；显式停止应取消，不能因重连复活。
- 会话归属检查和能力集合 digest 仍生效；跨买家、旧会话或伪造版本不得绕过原有保护。

此部分保留创建时的验收清单；后续代码复核结果见下节，最终浏览器结果由主任务另行记录。
