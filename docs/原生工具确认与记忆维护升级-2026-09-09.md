# 原生工具确认与记忆维护升级

保留 SQLite 事实与向量后端，没有安装 Mem0/ReMe。本次升级在既有订单、语义记忆交付基础上完成。

## AgentScope 原生确认

记忆工具通过 `MemoryPermissionMiddleware.on_check_permission` 返回 `PermissionDecision(ASK)`，由 AgentScope 2.0.6 生成 `RequireUserConfirmEvent` 并将调用保存为 ASKING。项目将其映射为 AG-UI `RUN_FINISHED.outcome.type=interrupt` 和待确认卡；这是等待买家决议，不是执行成功。

买家批准/拒绝 → 官方 AG-UI Client 提交 `resume` → 身份和会话归属校验 → 日志核验待确认 ID → 在会话锁/租约内读取当前 AgentState → 构造 `UserConfirmResultEvent` → 框架继续执行或拒绝。工具名和参数取服务端原调用，客户端不能改参数、提供工具实现或添加永久 allow 规则。恢复请求的决议参与 runId 幂等指纹；重放相同运行读取旧结果，复用 runId 改决议会被拒绝。

同会话有待确认操作时，不启动新的普通对话执行；页面提示先处理确认。刷新从服务端运行日志恢复卡片，AgentState 保存待执行调用。页面明确保存偏好本身已是用户操作，不另弹 Agent 工具审批。

订单创建/取消工具继续只准备持久业务确认资源，实际订单、报价、库存事务由买家点击原业务卡后提交，不额外增加第二次审批。工具注册与权限引擎仍由 AgentScope 管理。

## ID、版本、来源与冲突

`memory_facts` 新增 `version/source_kind/source_ref`。旧行原 ID 保留、默认版本 1；新行使用随机稳定 ID，修改保持 ID、版本递增。删除再添加同文偏好会产生新 ID，避免 ABA。事实、向量和版本在同一 SQLite 事务内更新。

页面和语义记忆 Agent 工具必须携带 `memory_id + expected_version`，服务端同时核验买家。更新和删除工具的 ID、版本是必填 schema；权限中间件在 ASK 前核对目标 ID、版本与展示原文，缺参或错指向不弹无效审批。旧页面没有版本时提示刷新；不允许仅按旧文本覆盖新记录。旧内部 `replace/delete` 方法保留兼容入口，但也转为读取版本后 CAS。提炼期间买家记忆列表发生变化时拒绝本次写入，防基于过期列表做冲突判断。

提炼器输出与已有事实冲突的 ID；追加遇到冲突不写入、不自动删旧记忆，要求明确编辑对应项。修改只允许解决指定目标的冲突；涉及其它记忆仍拒绝，不能连带覆盖。不同商品范围不视为同一偏好，例如蓝色上衣与蓝色裤子。

`memory_audit` 与事实操作同事务写入，记录创建/修改/删除、版本、来源类型、对话会话引用、来源哈希与时间；不复制原文或已删除事实正文。页面提供“变更记录”，查询按买家隔离。旧存量行只补迁移标识，不伪造历史操作记录。

删除移除事实与向量，但审计元数据保留；旧迁移源、独立对话流水和备份不是本接口的清除范围。

## 注入与范围

每轮继续由 AgentScope `BuyerMemoryMiddleware.on_reply` 注入最新召回结果，并带上可维护的 ID/版本。正向事实向量召回，负向约束全量保留，当前明确要求优先。

仅明确无商品范围的材质负向偏好映射为目录硬过滤。“不要塑料材质”可排除对应材质，“不喜欢塑料食品盒”不能扩大为排除所有塑料商品；范围化负向事实仍完整注入供 Agent 判断。规则匹配采取保守策略，复杂范围不会自动翻译成全局过滤。

## 验证与复现

- `tests/test_native_memory_confirmation.py` 使用真实 AgentScope Agent、权限中间件和 AgentState 序列化，覆盖批准/拒绝、恢复、旧确认重放、AG-UI interrupt 和日志决议指纹。
- `tests/test_memory_upgrade.py` 验证真实 SQLite CAS、并发单一胜者、ABA、跨买家、审计、提炼期间并发写入、HTTP 409 和商品范围。
- 前端使用官方 SDK 验证 `resume` 请求确实携带决议，组件测试覆盖审批操作。原订单交易测试保留。
- `eval/memory/cases.json` 提供 12 个合成样本；运行 `python -m scripts.evaluate_memory` 使用本机配置的真实模型，不修改买家记忆。结果写入 `eval/verification/memory-upgrade-20260909/extraction.json`。

12 个提炼样本覆盖噪声、临时需求、第三人称、假设、指令注入、否定、去重、商品范围和冲突；这是小样本规则评测，不是生产准确率。模型自报置信度与来源片段校验不等于完整事实蕴含证明；冲突识别仍依赖模型。没有引入自动全对话记忆采集、外部存储或自动过期删除。

原生 API 依据本机 AgentScope 2.0.6 源码及[官方确认示例](https://github.com/agentscope-ai/agentscope/blob/main/examples/realtime/local_mic.py)核对。长期记忆设计调研链接仍见[上一阶段记录](订单管理与语义长期记忆-2026-09-09.md)。
