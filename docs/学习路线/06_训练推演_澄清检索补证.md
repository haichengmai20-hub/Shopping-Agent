## 总览：06 在整个项目里做什么

**在整个项目里的位置。** 01–05 讲的是 Globex 现在怎样工作，06 设想把其中一部分交给训练。项目本身没有参数训练链路（见[项目全景](README.md#project-map)）。06 按 [项目定位与其他AI须知](../项目定位与其他AI须知.md) 推荐的窄任务，在[纵览](README.md#overview-all)第 ④ 站的 Agent 循环里，挑出「要不要追问、怎样检索、要不要补证据、什么时候作答」这组决策，搭一个能在 CPU 上跑的训练环境；再做一次完整的训练推演，参照 Code-R1 的实跑推演。代码在仓库根目录的 `agentic_rl/`，`app/` 一个文件没改。

**要回答的问题。** **在一个真实的 Agent 应用上做 Agentic RL，环境、奖励、数据和评测分别要怎样搭？训练奖励涨了、结果却一般时，怎样归因？**

**答案。**

- 环境：工具直接调用线上真实的商品检索，买家由规则化的模拟用户扮演，只检索、不下单，所以每条轨迹天然可重置。

- 评测：先跑规则基线。最好的规则在开发集上 100%，换说法的 held-out 上只有 10%，这才是需要训练的理由。
- 归因：run-01 的训练奖励涨到 1.0 附近，held-out 只有 0.31；三条原因各有证据，run-02 一次只改这三处。

## 文字版导读：先把全篇顺一遍

**第一节：任务和边界。** 只训主 Agent 自己调工具的那条路径，不训派发和下单。任务有五类场景：条件给齐、缺一个条件、根本没有合格商品、买家中途改条件、买家要求核对。预算一律按到手价理解，多数可行任务里都有陷阱商品。训练集和开发集用一组商品和 A 套说法，held-out 换一组商品，并改用 B 套说法（城市名代替国家名、口语开场白、「塑料」代替材质标签、更多中文数字）。详见[一、任务和边界](#task-6)。

**第二节：环境。** 动作空间和线上对齐，只有两个工具：线上真实的 `product_search_tool`，和沿用线上约定的 `show_shopping_form`（展示后结束本轮，等买家提交）。买家由规则化的模拟用户扮演：隐藏条件只在被问到时才回答，第一次作答后按场景追问。商品目录只读、任务不下单，所以每条轨迹都从同一份目录出发，绕开了线上「库存持久、不能重置」的难题。详见[二、环境](#env-6)。

**第三节：奖励。** 原版照教程 08-2 的五维加权公式实现，其中「商品相关性」用策略自己传的检索参数去核对推荐商品，而价格上限本来只比单件价，所以永远查不出到手价超支。补强版用不依赖策略行为的独立判定逐件核对：到手价不超预算、能配送、有库存、材质不在排除之列。缺条件的任务必须先问，要求核对的任务必须先按 ID 精确检索；推荐本轮没检索到的商品或泄露内部字段，直接记 -1。详见[三、奖励](#reward-6)。

**第四节：规则基线和 SFT 数据。** 四个规则策略的真实结果：careful（缺条件先问、按到手价核对）在开发集上 100%，但 held-out 只有 10%，因为规则词典只见过 A 套说法；trust_filter（相信价格上限）推荐了 37% 的陷阱商品，原版奖励照样给 1.01。careful 在训练集上的轨迹按 08-1 的五条红线清洗，320 条留下 319 条，作为 SFT 冷启动数据。详见[四、规则基线和 SFT 数据](#baseline-6)。

**第五节：配置和曲线。** 推演用 Qwen3-8B、4×A800、verl v0.6.0 的 GSPO 加多轮 rollout。run-01 照教程：原版奖励、clip 0.2、只用 A 套示范。曲线上训练奖励从 0.62 涨到 1.03，补强版核验的成功率却只到 0.78，陷阱推荐率始终在 0.3 上下、没有下降，`pg_clipfrac` 恒为 0。这三条曲线就是归因的线索。详见[五、配置和曲线](#runs-6)。

**第六节：评测和归因。** 固定协议：开发集 80 题选 checkpoint，held-out 120 题只评最终 checkpoint 一次。run-01 的 held-out 是 0.31，属于「结果一般」。三条原因：奖励有漏洞、clip 等于没开、SFT 示范分布窄。run-02 一次只改这三处，held-out 到 0.58，区间不重叠。新 clip 3e-4/4e-4 很窄，真跑时要先看前 10 步的裁剪比例。详见[六、评测和归因](#attribution-6)。

读完导读，按顺序读正文；作业在[七、作业](#assignments-6)，最后用[60 秒口述与面试追问](#oral-6)自测。

## 一、任务和边界：训什么，不训什么

**选这个任务的理由。** 项目定位文档列出的几个候选里，「约束缺失或变化时，怎样澄清、检索和补证」最适合做第一版：

- 动作少，只有追问、检索、作答三种。
- 对错能用商品目录独立判定，不需要 Judge。
- 它正好是 03 里 layered 策略下被正则规则替模型决定的那件事。

派发子 Agent、下单都先不训：前者让主轨迹看不到子 Agent 的内部决策（02 第四节），后者有副作用、环境要能回滚库存（03）。

**五类场景。** 每类场景考一种决策：

| 场景 | 买家怎么说 | 正确做法 | 考的决策 |
| --- | --- | --- | --- |
| complete | 商品、收货地、预算都给了 | 直接检索，按到手价核对后推荐 | 不该问就别问 |
| missing_slot | 缺收货地或预算 | 先用表单问清，再检索 | 该问就问 |
| no_result | 条件给齐，但没有商品同时满足 | 如实说没有，不擅自放宽条件 | 不编造、不放宽 |
| changed | 第一次作答后改了预算、收货地或材质 | 按新条件重新检索，淘汰旧候选 | 不沿用过期条件 |
| verify | 作答后要求核对第一个推荐的价格和库存 | 先用商品 ID 精确检索再回答 | 复核要先补证据 |

真实运行生成了三个切分，规模和配比如下：

| 切分 | 题数 | 场景（complete / missing_slot / no_result / changed / verify） | 商品 | 说法 |
| --- | --- | --- | --- | --- |
| train | 320 | 96 / 80 / 32 / 64 / 48 | 背包、保温杯、收纳盒等 7 类 | A 套 |
| dev | 80 | 24 / 20 / 8 / 16 / 12 | 同上 | A 套 |
| held-out | 120 | 36 / 30 / 12 / 24 / 18 | 台灯、耳机、洗护套装等 5 类，和训练集不重叠 | B 套 |

**预算口径和陷阱商品。** 预算一律按到手价理解，这正是 05 讲的缺口：线上价格上限只比单件价。「单件价不超过预算，到手价却超了」的商品叫陷阱商品。生成任务时，一半的可行任务会特意挑一个能制造陷阱的预算，其余的预算随机取，也常常碰上陷阱。结果训练集 288 道可行题里有 225 道带陷阱（78%）。

**为什么 held-out 要换说法。** 如果 held-out 只是训练句子的同义改写，规则也能拿高分，就看不出训练的价值。B 套说法故意换成训练集没出现过的表达，比如「寄到上海」「给我看看台灯」「别要塑料的」「三百块钱以内」，检验策略是理解了需求，还是只记住了句式。其中城市名和开场白是规则词典真正处理不了的；中文数字预算规则其实能解析，见第四节。

## 二、环境：可重置，动作和观察与线上对齐

**和线上的关系。**

~~~text
线上 Globex                          训练环境 agentic_rl
页面 → AG-UI → 编排器                 任务种子 → 模拟用户的第一句话
        |                                     |
        v                                     v
MainAgent 循环（AgentScope）          策略（规则或待训练模型）循环
        |                                     |
   商品检索工具  <---- 同一个函数 ---->   product_search_tool
   澄清表单工具  <---- 同一套约定 ---->   show_shopping_form
        |                                     |
会话、证据、库存持久保存               每条轨迹独立，目录只读
~~~

复用的部分：商品目录 v3、检索用例、汇率和报价规则，工具函数就是线上那一个。但训练环境没接 embedding、向量库和 rerank，检索走的是线上的兜底路径：关键词召回（`keyword_2gram`），按 ID 核对走精确查找。好处是确定、免费、不依赖外部服务；代价是召回效果不等于线上。新写的部分：Agent 循环、模拟用户、奖励。它们不经过线上编排器和 AG-UI，所以免费、可复现、本机能跑。代价是和线上有差距，写在[九、怎样复现和边界](#reproduce-6)。

动作空间只有两个工具：`product_search_tool` 和 `show_shopping_form`。派发工具（[02 第四节](02_AgentLoop与子Agent派发.md#dispatch-2)）在训练环境里不注册——主轨迹要记录每一步决策，子 Agent 的步骤会混进记录、结束原因又带不回来，先把动作空间收窄到可控。线上 Harness 往工具结果里追加的 `[harness]` 提示（[02 第三节](02_AgentLoop与子Agent派发.md#call-id-2)）这里也没有，这套环境等于「无护栏版本」，处理原则见[九、怎样复现和边界](#reproduce-6)。

**为什么能重置。** 03 讲过，线上的库存和会话持久保存，换一个数据目录又会重新做 embedding。训练环境只检索、不下单，商品目录只读，每条轨迹从「系统提示 + 买家第一句话」重新开始，轨迹之间没有共享的可变状态。这是有意收窄任务换来的；以后要训下单，就得补库存回滚。

**一条轨迹怎样走。**

~~~text
系统提示 + 买家第一句话
        |
        v
策略输出一步 ---- 带工具调用 ----> 执行工具，结果带同一个调用 ID 回到对话
   |                                        |
   |                       是表单：本轮结束，模拟用户按隐藏条件填表
   |                                        |
   +---- 不带工具调用（作答） <--------------+
        |
        v
模拟用户：第一次作答后按场景追问（改条件或要求核对），否则结束
~~~

上限照教程 08-2：助手最多 15 步，买家最多说 4 轮，撞上限记为 `max_turns`，不算正常完成。这和 02 讲的迭代上限是同一个概念。

**模拟用户。** 规则化：表单里问到哪个条件，就按任务的隐藏值回答；没被问到的不说。措辞跟着任务的说法风格走，held-out 的买家也用 B 套说法回答。不用另一个大模型扮演买家，是为了让真值可核验、避免引入噪声，这也是项目定位文档的建议。

**轨迹格式和 loss mask。** 一条轨迹存成一行 JSON，按 system、user、assistant（可带工具调用）、tool 的顺序排列，这就是 08-1 的多轮格式。只有 assistant 的内容计入 loss，工具返回只作上下文（04 讲过原因）。格式校验检查四件事：工具名合法、参数能解析、调用 ID 唯一、每个调用都有对应的工具回复。这正是 02 第三节的调用 ID 配对。

## 三、奖励：原版看参数，补强版看结果

**原版（教程 08-2）。** 照原文公式实现：0.40 回答质量 + 0.20 过程合规 + 0.15 Query 拆解 + 0.15 商品相关性 + 0.10 安全；安全不合格或 P0 失败时记 -1；每次工具调用成功加 0.01，同一工具连续 3 次扣 0.05。回答质量和 Query 拆解原文要用 Judge 和 BERTScore，CPU 上换成确定性的代理。

**漏洞在「商品相关性」。** 原文说「约束来自工具入参」：用策略自己最后一次检索传的参数去核对推荐商品。问题是：

- 策略传的价格上限，本来就只比单件价。
- P0 只拦单件价超过预算 1.5 倍的商品。

所以一件「单件价 280、到手价 305、预算 300」的陷阱商品，在原版奖励眼里完全合格。策略能学到的是「把预算填进参数」，学不到「核对到手价」。这正是 02 第二节那个习惯在奖励设计上的翻版：参数传对了，不等于结果对了。

这条漏洞出在商品相关性和 P0，两项都照原文实现。占 0.40 的回答质量用的是代理；换成真 Judge，并且让它看到到手价，可能会扣掉一部分，这一点没有测过。

**补强版。** 不看策略传了什么参数，用独立判定逐件核对推荐结果。判定复用线上的报价规则，按到手价计算：

| 检查 | 不通过的后果 |
| --- | --- |
| 推荐商品的到手价、配送、库存、材质、是否就是要找的商品 | 本题失败 |
| 有合格商品却没推荐；没有合格商品却推荐了，或没说清楚「没有」 | 本题失败 |
| 缺条件的任务，在第一次作答前没问到那个条件 | 本题失败 |
| 要求核对的任务，追问之后没有按商品 ID 精确检索 | 本题失败 |
| 推荐了本轮检索里没出现过的商品，或回答里泄露工具名、内部字段 | 直接记 -1（P0） |

成功记 1，再按成本扣分；失败记 0，成本不倒扣：每个多余的问题扣 0.05（最多 0.3），多余的检索每次扣 0.02，同参数重复调用 3 次扣 0.1。只有 P0 才记 -1。成本只在成功时扣是有意的：失败若记负分，GRPO 组内标准化后，全错的组里「少问一步」的轨迹反而拿到正优势（第六节有算例），策略会学成「失败了也少问」。这样「每题都把所有条件问一遍」的策略虽然也能成功，奖励会更低。

**两个已知局限**（设计使然，暂不改代码）：回答里提到已排除的商品 ID，比如解释「避开了 P1234 的塑料材质」，这个 ID 也会被当成推荐逐件核对而判失败——策略学会不提排除项就能过关，但诚实的解释被惩罚了；可行任务里先说「没有找到」再给合格 ID 仍算成功——自相矛盾的回答识破不了。真跑前可以考虑只核对推荐句式里的 ID，或给判定加一致性检查。

**怎样认「推荐」。** 只看最后一次作答里出现的商品 ID：不写 ID 就算没推荐，可行题直接失败；回答里出现的每个 ID 都逐件核对。没有合格商品时，回答里不能出现任何 ID，还要明确说「没有找到」这类话（`reward.py` 的 `recommended_ids` 和 `NO_RESULT`）。2026-11-01 起，幻觉与泄露检查覆盖**每一次**作答，不再只看终答；任务层的「推荐」判定仍以终答为准。

**放到 04 里看。** 补强版就是 04 讲的「确定性断言是奖励的骨架，但要补检查、防投机」：P0 保留成硬约束，不和其他项加权混在一起；成本项防止「多问总不会错」这种投机。

## 四、规则基线和 SFT 数据：先证明需要训练

项目定位文档要求先设规则基线：如果「问完槽位再搜」的规则已经能稳定解决，就不上 RL。四个规则策略共用同一套解析词典，词典只覆盖 A 套说法，这正是写规则的人只见过训练集时的真实处境：

| 策略 | 做法 |
| --- | --- |
| careful | 缺收货地或预算先问；检索后按到手价逐件核对再推荐 |
| trust_filter | 同样会问，但相信价格上限，不核对到手价 |
| always_ask | 不管条件给没给齐，开局把收货地、预算、材质全问一遍 |
| never_ask | 从不追问，缺收货地默认寄中国，缺预算就不设上限 |

**真实运行的结果**（`eval/verification/agentic-rl-env-20261019/baselines/tables.md`）：

| 策略 | train 成功率 | dev 成功率 | held-out 成功率 | train 陷阱推荐率 | 原版奖励（train） | 两版奖励的相关系数（train） |
| --- | --- | --- | --- | --- | --- | --- |
| careful | 0.997 | 1.000 | 0.100 | 0.000 | 1.004 | -0.02 |
| trust_filter | 0.566 | 0.613 | 0.100 | 0.372 | 1.015 | 0.08 |
| always_ask | 0.997 | 1.000 | 0.100 | 0.000 | 1.011 | -0.02 |
| never_ask | 0.747 | 0.750 | 0.100 | 0.049 | 0.902 | 0.39 |

三个读法：

- **原版奖励分不出好坏。** 四个策略的原版奖励都在 0.9 到 1.0 左右，和真实成功率只有弱相关。trust_filter 推荐了 37% 的陷阱商品，原版奖励反而最高。相关系数是在每个策略内部算的：careful、always_ask 的成功率几乎恒为 1，它们的 r 没有信息量；有信息量的是 trust_filter（成功率在变，r 只有 0.08）和策略之间的排序。把四个策略在 train 上的 1280 条轨迹合起来算，原版奖励和「补强版判成功」的相关系数是 0.24（2026-10-20、10-21 两次用同一套代码现算：0.24、0.236，未落盘）。更直接的证据在 held-out：四个规则的成功率都是 0.10，原版奖励却都在 1.01–1.02。在这版实现里，检索一次再说「没有找到」就能拿满分，因为不推荐时商品相关性记 1。
- **成本项有用。** always_ask 和 careful 成功率一样，但补强版奖励低（0.86 对 0.997），因为它每题都多问。
- **规则泛化不了。** careful 在开发集上 100%，held-out 只有 10%。失败卡在两处：词典认不出城市名，「寄到上海」解析不出收货地，规则每题都去追问（多余追问率 1.0），问完也还是未指定；B 套开场白剥不掉，「给我看看收纳包」整句被当成商品词，按标题过滤后一件不剩。中文数字预算它其实能解析，不是失败原因。120 题里 108 题最后没有给出推荐；答对的 12 题全是「本来就没有合格商品」的场景，碰巧说对了「没有」。这就是需要训练的理由：要的是理解需求，不是匹配句式。

**SFT 冷启动数据。** 用 careful 在训练集上的 320 条真实轨迹，按 08-1 的五条红线清洗：

| 红线 | 处理 |
| --- | --- |
| 同一工具连续调用 4 次及以上 | 整条删除 |
| 估算 token 超过 16384 | 整条剔除（2026-11-01 起；原来照 08-1 截断保留，但本实现的截断必丢终局作答，示范不完整） |
| 工具名、参数、调用 ID、工具回复配对任一不合格 | 整条删除 |
| 回答里泄露内部工具名或字段 | 整条删除 |
| 补强版判失败，或奖励低于 0.9 | 不入库 |

结果是 320 条留下 319 条，删掉的 1 条是分数不达标。平均每条约 3400 token（按字数估算）。这批数据有个隐患，后面归因会用到：它全部来自 A 套说法。

## 六、评测和归因：一轮结果一般，下一轮改什么

**协议先定。** 开发集 80 题选 checkpoint；held-out 120 题只在最终 checkpoint 上评一次。成功率一律按补强版核验，和训练用哪版奖励无关（2026-11-01 起默认口径为安全成功：任务成功且无 P0；任务成功单列，见改动记录 2026-11-01）。

**结果**（`eval/results.md`）：

| --- | --- | --- | --- | --- | --- | --- |
| careful 规则 | 1.00 | 0.10 | 0.06–0.17 | 0.00 | 1.00 | 真实运行 |
| Qwen3-8B 只用提示词 | — | 0.19 | — | — | — | 推演 |

| 只加 C 改写（其余同 run-01） | — | 0.38 | — | 0.30 | — | 推演（消融假设） |

careful 的 held-out 陷阱率 0.00 没有信息量：120 题里 108 题根本没给推荐。区间不重叠可以说明差异显著，但判据偏保守；两轮评的是同一批 120 题，真跑时应改用配对检验（McNemar）。

**run-01 为什么一般：三条原因，每条都有证据**（`attribution.md`）：

1. **奖励有漏洞。** 证据来自真实运行：trust_filter 推荐了 37% 的陷阱商品，原版奖励仍给 1.01，它内部两版奖励的相关系数只有 0.08。run-01 的陷阱推荐率一直不降，说明策略学的是「把预算填进参数」。
2. **clip 等于没开。** 证据来自真实运行的 GSPO 演示：GSPO 把整条回答的对数比率取平均，噪声被压小约 √L 倍。每 token 噪声 0.05、回答 800 token 时，序列级标准差约 0.0018，±0.2 区间外的比例是 0，所以 `pg_clipfrac` 恒为 0。L 只算 loss mask 内的 assistant token：规则示范里平均约 220（按字数估算），演示在 200 和 2000 token 时也都是 0，结论不受长度影响。教程把 token 级 PPO 常用的 0.1–0.2 搬到了序列级；GSPO 论文用的是 3e-4/4e-4。「比率恒为 1」这个平凡解释也排除了：配置里每步 32 题 × 8 条采样切成 32 个 mini-batch（每块恰好一组）、跑 2 个 epoch，除第一次更新外都是离策略的。两点边界：√L 只对独立噪声成立，有方向的漂移不会被平均压小；但即使每个 token 都同向漂移 0.05（演示的量级），序列比率也只有 e^0.05≈1.05，仍在 ±0.2 之内，结论不变；这条证明的是配置失效，它对 held-out 0.31 贡献多少，演示证明不了。
3. **SFT 示范分布窄。** 证据来自真实运行：careful 规则在 held-out 上只有 10%，示范全是 A 套说法。RL 的起点在 held-out 上就弱，run-01 的多余追问率 0.42 说明 RL 没把这个毛病练掉。

**排除了什么。**

- 不是训练没收敛：KL 稳定、熵平缓下降，没有崩塌信号。
- 不是评测噪声：dev 0.86 和 held-out 0.31 的差距远超区间宽度。
- 不是模型容量：同一个 8B 在 run-02 到了 0.58。这条用的是推演数字，真跑之后才算证据。

**run-02 一次只改有证据的三处**：

| 改动 | 对应原因 | 代价 |
| --- | --- | --- |
| 奖励换成补强版 | 1 | 奖励更稀疏，前 40 步上升慢 |
| clip 改成 3e-4/4e-4 | 2 | 区间很窄，对每步策略漂移非常敏感 |
| SFT 示范加入 C 风格改写（同样的轨迹，买家消息换成和 A、B 都不重叠的第三套说法） | 3 | 改写要人工审核，示范从 319 条增到约 640 条。改写不用 B 套：B 是评测集的说话方式，泄进训练，held-out 就不再是「没见过」 |

学习率、KL 系数、采样组大小、步数都不动，免得改太多说不清是哪一处起的作用。但三处是一起改的，0.58 拆不出各自的贡献；「其他参数不动」只保证不混进第四个因素。上面表里三行单因素消融是参数模型的假设，不是任何真实运行：它们说明三处为什么都要改（只换 clip 只到 0.34，只加改写只到 0.38，都不及 0.58），真实归因要真跑消融，三组约 ¥3,200、超出单轮预算，可先只跑「只换奖励」一组验证主因。

**「奖励更稀疏」具体指什么，成本项的坑怎样避开。** 8 条采样全错、或全对且成本相同的组，组内优势全是 0，没有梯度——这是「稀疏」的代价。更隐蔽的坑是成本倒扣：最早一版失败记负分，全错但成本不同的组里，0 和 -0.05 这点差会被组内标准化放大成 +0.35 和 -2.47 的优势（用 `gspo.group_advantages` 对 `[0]*7 + [-0.05]` 可以直接算出来），这一组教给策略的只有「少问」，和成功无关。2026-10-21 起成本只在成功时扣、失败一律 0 分（`reward.py` 有注释、`tests/test_agentic_rl.py` 有单测），这个伪信号就没有了。

**新 clip 要先核对。** 同一个真实演示也给出了反面：按演示的设定（每 token 噪声 0.05），3e-4/4e-4 在序列级会裁掉 75%–93% 的样本，几乎每步都在截断。推演给 run-02 设的裁剪比例约 0.15，按 800 token 倒推出每 token 漂移约 0.007（按示范实测的约 220 token 算约 0.004），都比演示小一个数量级，这是假设，不是实测。真跑时先看前 10 步的 `pg_clipfrac`：持续高于 0.5，说明区间对当前步长太窄，先把学习率减半；接近 0，就检查损失是否真的是 GSPO。

**结论的边界。** run-02 对 run-01 的提升（0.31 → 0.58）区间不重叠，但这是推演数字。改写特意用和 B 不重叠的 C 套说法——如果用 B 套改写，等于把评测集的说话方式泄进训练，held-out 的提升会虚高；这是数据卫生问题，真跑前要检查改写词表和评测词表不重叠。C 套也是人工写的小词表，覆盖不了真实买家的多样性。真实运行能证明的只有三件事：原版奖励有漏洞、规则泛化不了、序列级 clip 的量级问题。

## 八、参考答案

**作业 A。**

1. 只看原版奖励会选 trust_filter（1.015 最高），只看补强版会选 careful。原版奖励按策略自己传的参数核对，看不见陷阱商品，所以「不核对到手价」反而不扣分；两个答案不同，说明奖励本身有漏洞。
2. always_ask 每题都多问了没必要的条件，补强版每个多余问题扣 0.05，所以平均 0.86。去掉成本项，「多问总不会错」就成了最优策略，训出来的模型会每题都填表，买家体验变差。
3. 全是 no_result 场景：本来就没有合格商品。规则认不出城市名、多问了一轮，又把开场白连同商品名当成了商品词，按标题过滤后一件不剩，于是说「没有找到」，碰巧对了。它说明规则对的是「不编造」这条底线，不是理解了需求。

**作业 B。** 三条原因和改动见[第六节](#attribution-6)。不改的参数：学习率、KL 系数、采样组大小、步数。曲线显示训练没崩、KL 稳定，没有证据指向它们；一次改太多，run-02 变好了也说不清是哪一处起的作用。

**作业 C。**

1. 训练环境只检索、不下单，商品目录只读，每条轨迹从种子重新开始；线上的库存、会话持久保存，换目录又要重新 embedding。放弃的是下单、取消这类有副作用的决策，要训它们就得补库存回滚。
2. 价格上限只比单件价，P0 又只拦单件价超过预算 1.5 倍的商品；陷阱商品的单件价在预算内，按参数核对永远合格。要发现它，必须按到手价独立核对。
3. 工具返回是环境给的观察，不是模型要学会生成的内容。计入 loss 会让模型学着「编造工具结果」，推理时可能不调工具，自己写一段假结果。
4. 只换商品，规则词典照样能解析句式，看不出泛化；只换说法，商品重叠，可能是记住了具体商品。两样都换，才能检验策略是不是理解了需求。
5. GSPO 先对整条回答取平均，序列级比率的噪声被压小约 √L 倍，±0.2 几乎永远不触发，等于没有 clip。换成 3e-4/4e-4 后要盯 `pg_clipfrac`：太高说明区间对当前步长太窄，接近 0 说明还是没生效。
6. 不能，那是推演数字，只能说「做过一次完整的训练推演」。有真实运行证据的是：原版奖励和真实成功率只有弱相关（held-out 上规则成功率 0.10，原版奖励仍有 1.02）；规则基线在开发集上 100%、held-out 上 10%；SFT 清洗 320 留 319；序列级 clip 0.2 不触发。

**和线上的差距**（写清楚，免得把推演当实测）：

- Agent 循环、模拟用户、奖励是平行模块，不经过线上编排器、AG-UI 和 Harness 中间件。线上 layered 策略下的正则补证规则，训练前要关掉或绕开（`CLAUDE.md` 第 6 节）。线上 Harness 往工具结果里追加的 `[harness]` 提示（顺序拒绝、重复提示）属于模型实际看到的观察，训练时应当作环境反馈保留、不要剔除——上线时模型同样会看到，剔掉会让训练和推理的观察不一致；本环境没挂这些中间件，是差距之一。
- 检索只走关键词召回，没接线上的 embedding 和 rerank（`env.py` 只给检索用例传了商品仓储）。换成线上召回后，候选集会变，规则基线和奖励对照要重跑。
- token 数按字数估算，真实训练要用 Qwen3 的 tokenizer 和对话模板重算 loss mask。
- 模拟用户是规则化的，买家真实的说法比 B 套更多样。
- 线上拿不到 logprob；真训练要把策略换成自建的推理服务。

## 60 秒口述与面试追问

**60 秒口述。** Globex 是一个跨境电商选购 Agent，本身没有训练链路。我在它上面挑了一个窄任务：约束缺失或变化时，模型怎样在追问、检索、复核、作答之间做决定。环境直接调用线上真实的检索工具，买家由规则化模拟用户扮演，只检索、不下单，所以每条轨迹都能重置。先在 CPU 上真实跑了规则基线，发现两件事。一是教程的原版奖励按策略自己传的参数打分，看不见「单件价合格、到手价超预算」的陷阱商品，和真实成功率只有弱相关；我补了一版按到手价逐件核对的奖励。二是最好的规则在开发集上 100%，换说法的 held-out 上只有 10%，这才是需要训练的理由。然后做了一次两轮的训练推演：run-01 照教程，训练奖励到 1.0，held-out 只有 0.31；归因为奖励漏洞、序列级 clip 不触发、SFT 数据分布窄，run-02 一次只改这三处（改写用与评测集不重叠的说法，避免把评测的说话方式泄进训练），到了 0.58。推演数字不是实测，真实证据是那几条基线结论。

**面试追问。**

| 追问 | 答题要点 |
| --- | --- |
| 训练奖励一直涨，为什么说结果一般？ | 训练奖励只说明策略学会了奖励；要配一条独立核验的成功率曲线，再看固定协议下的 held-out。run-01 两者不同步，陷阱推荐率不降，说明奖励有漏洞 |
| 你怎么发现奖励有漏洞的？ | 先跑规则基线：故意不核对到手价的策略，原版奖励反而最高，两版奖励的相关系数接近 0。上训练之前，用对照策略给奖励「做体检」 |
| 环境怎么重置？线上为什么不行？ | 线上库存和会话持久，换目录要重新 embedding；训练环境只检索、不下单、目录只读，每条轨迹从种子开始。代价是暂时训不了下单 |
| GSPO 的 clip 为什么是 3e-4？ | 序列级比率是 token 对数比率的平均，噪声被压小约 √L 倍，0.2 永远不触发；但 3e-4 很窄，要盯 `pg_clipfrac`，太高就先减学习率 |
| 为什么不直接用 Judge 打分做奖励？ | 这个任务的对错能用商品目录独立判定，确定性、零噪声、不能被策略讨好；Judge 留给表达质量这类判定不了的部分，并且要先校准 |
| 规则已经很好了，为什么还要 RL？ | 规则只在见过的说法上好；held-out 换了说法就掉到 10%。如果规则在 held-out 上也稳定，就不该上 RL，这是先跑基线的意义 |
