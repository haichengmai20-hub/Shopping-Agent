# 贯穿例子维护记录

学习路线的五个阶段共用一个商品例子。这份文档是它的唯一登记处：例子是什么、允许怎样变化、哪些地方是例外，以及每次修改改了哪里。用户 2026-10-19 要求：改商品例子要用一个文档来维护记录。

<a id="definition"></a>
## 例子是什么

> 帮我找一件轻便背包，寄到中国，总到手价不超过 300 元人民币。

原句出自[第一阶段](01_项目地图与前后端流程.md)。三个要素：轻便背包；寄中国（工具参数 `ship_to=CN`，币种 `CNY`）；300 元人民币。

**预算口径**：当前代码用 `price_max_major` 过滤的是换算到目标币种后的单件商品价（`CatalogSearchUseCase._within_price_cap()`）；到手价 `landed_price` 由 `_to_card()` 另行计算，而且只按数量 1 报价。所以「总到手价不超过 300」是需要核对的任务要求，不是代码已经硬性保证的过滤。[第五阶段](05_商品检索与前后端闭环.md)的主例因此写成「单件商品价不超过 300，同时告诉我到手价」，并拿「总到手价不超过 300」做对照。

**和商品目录对得上的事实**（2026-10-19 查 `data/catalog-v3.jsonl`）：标题或描述含「背包」的商品共 18 个，都在「旅行装备」类目，材质标签全是「合成聚合物」。型号有：

- BudgetPack 20L 简易背包（人民币标价 39）；
- DryPack 30L 防水卷口背包（219）；
- Roamix 登山背包 GX-01 的 15L、25L、35L、45L 四款，35L 起配防雨罩。45L 款有一个人民币标价 343 的商品可寄中国，会被 300 元上限滤掉。

<a id="variants"></a>
## 允许的变化

在例子内部变化条件，不另换商品：

| 阶段 | 变化 | 为什么这样变 |
| --- | --- | --- |
| 02 | 「第一次买轻便背包，先讲选购要点，再推荐商品」 | 演示先查品类知识、再检索的两步工具循环 |
| 02 | 并行派发拆成两个背包子任务：日用、25L 以内；徒步、30L 以上、防水或配防雨罩 | 派发需要两个互相独立的子任务。不按材质拆，因为目录里的背包材质标签都一样 |
| 03 | 预算从 300 改成 250，再比较前两个候选 | 演示新需求怎样替代旧需求 |
| 04 | 教学数据：标价 280 + 运费 25 + 关税 0 = 到手价 305，超过 300（和第五阶段作业 B 的商品 A 相同，运费和关税符合代码对寄中国旅行装备的规则） | 演示「单件价过了、到手价超了」的检查缺口 |
| 05 | 「单件商品价不超过 300 + 告诉我到手价」，对照「总到手价不超过 300」 | 讲清代码保障的范围 |

<a id="exceptions"></a>
## 例外（设计使然，不改）

- **04 的 agent-001**：分析的是仓库里的真实评测用例（`eval/v1/agent_cases.yaml`，「我需要旅行装备，请推荐一件可寄到 CN 的现货」），不能为了统一去改评测数据。
- **docxs 教程原件**：只读，里面的「旅行三件套寄美国」等例子保持不变。
- **03 的长期偏好「以后偏好轻便设计」**：保留。它和本次任务里的「轻便背包」放在一起，正好说明同一个属性既可以是这一次的约束，也可以在买家明确说「以后」时成为长期偏好。
- **06 训练推演的任务集**（2026-10-20 登记）：训练任务由 `agentic_rl/tasks.py` 从商品目录自动生成，训练集用背包、保温杯、收纳盒等 7 类，held-out 换成台灯、耳机等 5 类，预算按到手价随机取。为了检验泛化，任务必须覆盖多种商品，不能只用背包；06 正文讲机制时仍用「轻便背包、寄中国、300 元」举例（陷阱商品的例子是单件价 280、到手价 305，与 04、05 一致）。
- **历史记录**：[2026-09-26 第一阶段改动记录](../改动记录/2026-09-26/第一阶段学习材料.md)和 `eval/verification/` 里的历史报告提到过保温杯，它们是历史证据，不改写。

<a id="maintenance"></a>
## 以后怎样维护

1. 任何一篇要新增、更换或调整商品例子时，先在这里登记：变化写进「允许的变化」或「例外」，再在「修改记录」下加一节，逐处写清阶段、位置、原来和现在。
2. 新例子里的商品、价格、容量要和商品目录对得上；对不上的数字明确标为「教学数据」。
3. 改完做三项检查：旧关键词和旧金额的残留检查；ASCII 图对齐检查（中文按两列算）；落盘检查（见仓库根目录 `CLAUDE.md`）。
4. 在[学习改动记录](学习改动记录.md)记一行，链接回这里。
