# Skill 与审核策略版本管理

本轮实现 `CapabilityRegistry`、两个只读 AgentScope 工具、本机审核 CLI、持久会话版本固定与主 Agent 接线。生产启动只创建空库，不自动发布示例；`docs/capabilities/` 的两份文件明确为待审核草稿。

## 使用方式

Skill 的 id、明确 version、标题、简述、scope、允许工具和内容 SHA256 进入主 Agent 的常驻摘要，正文不提前注入。主 Agent 判断相关后调用 `load_agent_skill_tool(skill_id, version)` 才取得指定版本正文。工具先检查发布状态、有效期、撤销状态和 hash，再校验当前实际 toolkit 包含其声明的工具。

白名单仅含现有只读商品检索、品类知识、会话事实、订单查询与可选联网搜索；不允许偏好写入、交易批准、Shell、文件执行或动态注册。Skill 不能安装新工具或提升权限；CLI 导入未知权限字段或超出白名单会失败。联网能力未配置时，依赖它的 Skill 不进入当前摘要，显式读取也失败。

`lookup_strategy_memory_tool(query, scope)` 只读取已审核发布、未过期、未撤销的策略，最多返回三条。策略包含证据引用、证据说明、适用 scope、关键词、到期时间、不可变版本/hash与审核人。检索按明确关键词匹配与 scope 过滤，不假装是向量学习或自动提炼。它与买家偏好库完全独立，没有写偏好或改预算、目的地、禁忌等硬约束的接口。策略只能作为建议。

## 审核与发布

从工程根运行。以下示例需操作员先查看正文与证据，再把审核人、发布人和证据参数换成真实记录；代码不会代替操作员自动审核。

```bash
uv run python -m scripts.capabilities import docs/capabilities/backpack-skill.draft.json --author operator
uv run python -m scripts.capabilities show skill backpack-selection 1.0
uv run python -m scripts.capabilities review skill backpack-selection 1.0 --reviewer reviewer --evidence review-ticket-123
uv run python -m scripts.capabilities publish skill backpack-selection 1.0 --publisher operator --evidence verified-regression-123
uv run python -m scripts.capabilities list
uv run python -m scripts.capabilities audit
uv run python -m scripts.capabilities revoke skill backpack-selection 1.0 --actor reviewer --reason evidence-no-longer-valid
```

策略草稿用相同流程，kind 参数改为 strategy，id 为 explain-price-scope。默认库是 `DATA_DIR/capabilities.db`；可用全局参数 `--db /tmp/isolated-capabilities.db` 验证完整流程而不触碰生产资料。相同 kind/id/version 不可覆写不同内容；改正文、scope、证据、白名单或有效期必须新建版本再审核。已撤销版本不能再次发布。审计表追加 import/review/publish/revoke、操作员、证据/理由和内容 hash。

本机 CLI 操作员字段是声明式审计，不等于企业身份系统认证；写入权限依赖主机/数据库访问控制。没有对外发布 API，也没有 Agent 可调用的审核、发布或撤销工具。证据引用不会自动下载、执行或被系统认定为真实，审核人需要核查。

## 会话与缓存版本

Prompt 版本固定提示词和工具契约；执行的资料版本另以 `capability_digest` 固定当前有效 Skill/策略版本集合。首次会话用可信 buyer/session 原子绑定 digest，后续恢复或复用 Agent 前必须匹配。发布、到期、撤销改变生效集合后，旧会话明确停止并提示新建选购会话，不能悄悄更新摘要，也不能把旧 Skill 正文重新送进下一轮模型。工具每次读取也复核当前会话版本。

digest 进入 ShoppingContext、脱敏 trace/event 关联，并加入 semantic cache 版本维度。旧建议不会跨资料集合复用。策略元数据与正文 hash 不进入买家偏好，也不改变用户约束。撤销不删除已经展示的历史回复；已经在模型中生成的文字无法追溯撤回，旧会话下一轮会被阻断。当前策略集作为一个整体固定，发布一条新策略也会要求已有会话新建，这是本地实现选择的保守边界。

冻结后独立审查发现并修复了“会话绑定后、读取资料前恰好发布新版本”的竞争窗口：metadata、load_skill 和 lookup_strategies 都接收本轮 expected_digest，在读取资料的同一 SQLite BEGIN IMMEDIATE 事务内校验有效版本集合，不能先独立检查、再另一个事务读新资料。工厂摘要与两工具共用本轮 ShoppingContext digest。竞争发生时明确返回版本变化错误，不把新资料配上旧 trace/cache 版本。

## 验证

```bash
uv run python -m pytest -q tests/test_capability_registry.py tests/test_prompt_registry.py tests/test_session_fencing.py --junitxml=/tmp/globex-capability-tests.xml
cd frontend
npm test -- --run
npm run build
```

实测后端本组 **58 passed in 2.85s**（其中新增 11 项，包含参数化场景），前端 **65 passed**，production build 通过。新增测试覆盖未审核不能读取/发布、不可变版本、工具扩权拒绝、正文按需、证据与 scope、到期/撤销、并发同版本导入竞争、内容篡改失败关闭、会话旧正文阻断、真实 AgentScope FunctionTool 构造、本机 CLI 审核发布流程。所有发布记录均写临时测试库，不声称生产草稿已由人审核。

版本读取竞争修复后追加 3 项确定性回归：绑定返回前发布 v2，再读取 Skill、策略或工厂摘要，三者均拒绝混用资料；后端相同组合最新 **61 passed in 2.22s**，报告 `/tmp/globex-capability-toctou-tests.xml`。这次源码不同于之前的正式评测快照，最终全量回归需基于修复后源码重新执行。
