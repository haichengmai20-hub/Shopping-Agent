# 上下文与检索：实现与验证

本记录对应计划第6、7项。本地代码与行为测试已实现；检索实验默认不改变正式主链。

## 上下文与预算

- `TOKEN_BUDGET_TOTAL>0` 时，每次模型请求在取得共享配额前同步预留输入估算+输出上限，并在完成时按 usage 结算。并行子协程共享同一账本，重试与备用模型也重新预留。预算不足直接返回规则 `ChatResponse`，不进入上游或新增派发。
- 缺少目标模型 tokenizer 时，输入按 UTF-8 字节及协议余量保守估算，输出通过 `max_completion_tokens` 限制。中断、失败或没有 usage 的已发出请求按预留值记账；这不是网关账单的精确计费证明。0仍表示关闭请求预算。
- 规则回复只整理当前轮由真实业务工具校验过的商品与交易事实；下一轮清空账本和兜底事实。预算不足导致 SDK 摘要工具模式无法生成结构化摘要时，编排层退出摘要，仍返回规则整理结果。
- 商品工具事件与 SQLite 冷证据保留完整商品卡；给模型的投影去除图片、展示文案等冗余，保留顺序、SKU、金额币种、库存、配送、材质、重量和到手价。5张“旅行背包”卡的 JSON 从6285字符降至4837字符，减少23.04%；这是字符数，不冒充 token 或线上成本降幅。
- 每份完整证据有不可变 `result_ref` 和 SHA-256，读路径核验 buyer/session。`conversation_fact_lookup` 支持引用、关键词、候选序号定点回查；历史结果明确标记历史，不代表当前订单授权或库存。
- 候选按会话持久 fence 和完成时间排序，较旧执行者的迟到结果不能反转最新候选。新一轮空结果会取代旧候选；压缩或重启后“第二个”仍可按最新证据解析。
- 压缩采用两阶段：超窗口阈值后先归档旧工具大正文，保留工具调用关系与引用，再让 SDK 重新计数，必要时才做摘要。记录压缩前后 token、是否摘要、摘要 hash、归档数和耗时。
- 每轮重建当前持久偏好提示，移除旧偏好/交易提示；偏好 revision 为当前内容指纹并持久记录。撤回后的旧摘要不得恢复该偏好。交易精确事实每轮从权威账本恢复。
- 子 Agent 返回结构化的结论、证据引用和已核实标识；出现未能由本轮工具证据核实的商品标识时标为 `unverified`，主 Agent 需再查询，不能直接当可信交易参数。

## Hybrid 与索引

`HYBRID_RECALL_ENABLED=1` 打开 BM25 与向量并行召回、RRF 融合、同款去重与原有重排。硬约束在候选截断前统一过滤；向量侧不足时扩大候选深度，最多256条。向量或重排故障如实输出 `bm25` / `hybrid_only`，成功才是 `hybrid_rerank`。默认0保留原链路，实验未通过不自动发布。

冻结150条正式商品数据上的本地词项对比：

| 词项链路 | Recall@8 | MRR | NDCG@8 | 硬约束/无结果准确率 |
|---|---:|---:|---:|---:|
| 原 keyword_2gram | 0.8800 | 0.8880 | 0.8797 | 1.0 / 1.0 |
| BM25 | 0.8800 | 0.8827 | 0.8682 | 1.0 / 1.0 |

该结果没有证明 BM25 排序收益，更不能证明 Hybrid 在线收益，因此保留默认关闭。原始逐条证据、输入 hash、分桶与耗时在[词项对比报告](../eval/verification/hybrid-20260909/lexical-comparison.json)，运行前后相关源码/数据指纹相同。复现：`.venv/bin/python scripts/eval/compare_lexical.py`。

知识索引 hash 包含正文、来源/时效元数据和分块配置。相同 ID 有变化时替换旧 chunk，受本同步器管理的文件删除后清理对应文档。源目录不存在时不删除；不删除其他来源的非托管文档。AgentScope当前接口不支持原子切换文档版本，更新采取先删后写，失败时允许暂缺，避免继续返回旧政策；下一次同步重试。真实本地 Qdrant 测试验证了同 ID 内容更新、删除、幂等和不残留旧内容。

## 验证边界

定向回归包括预算耗尽上游调用为0、并行预留、重试扣费、流关闭、证据跨身份拒绝、重启回查、旧fence迟到、偏好撤回、两阶段压缩、RRF、硬约束、适应性补召回和真实Qdrant更新/删除。完整最终回归数量见本轮总交付记录。

真实重排网关目前返回未找到模型服务，正式在线主链及Hybrid在线收益仍待外部配置恢复后验收。上下文证据以本地SQLite持久化，仍需按实际数据保留策略管理容量；未实现自适应压缩阈值和显式Prompt Cache，这两项仍按原计划等待测量证据。

## 精确实体与知识覆盖修复

完整冻结 Agent release 中，三个确认场景因 P2206 / P2222 / P2239 未进入向量候选而失败。已增加 `exact_id_lookup`：从查询中保留完整商品/SKU ID，直接核对商品仓储，按输入顺序返回、仍执行库存/配送/材料/预算约束；缺失 SKU 不替换为同款其他 SKU。仅 `existence_checked=true` 的 `missing_identifiers` 可以证明目录中不存在该 ID。此确定性路径不声称调用了 embedding/reranker；正式评测如要求纯在线精排，仍应如实记录策略并阻断。

知识检索改为以文档覆盖为单位：先扩大向量片段候选并去重；查询明确提到登记标题时，按最具体标题及出现顺序覆盖主题；目标文档未进入候选时，在保留原 metadata_filter 的只读知识库视图中补查其来源文档。只指定政策地域时优先通则，具体商品、税额、未来价格等确定事实请求需要结构化或实时证据，缺参不会由最近邻补成事实。分数保留实际向量值，政策来源/时效仍单独判定。

开发集诊断（35 条，`eval/verification/knowledge-improvement-20260909/dev-v2.json`）Recall/MRR/NDCG、不可回答准确率及政策拒答准确率均为 1.0。该数据集包含标题直接匹配的合成问题，不能据此推断真实业务全面正确；正式 release 结果单独记录，不在开发过程中修改金标或放宽门槛。旧冻结版本报告保留。

商品卡展示顺序与模型正文序号曾出现不一致。Prompt 已要求正文保持 hits 顺序并附商品 ID；历史“第二个”按最近商品卡的持久顺序回查。目录中的宣传重量和结构化重量也存在矛盾，Prompt 要求明确数据差异；本轮没有把模型选择的数字回写目录或当作新金标。
